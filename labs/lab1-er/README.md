# Lab 1 - ER-модель: FoodDelivery

## Домен
FoodDelivery — платформа для замовлення та доставки їжі.

## Чому цей домен
Обрав FoodDelivery, оскільки це цікаве завдання ,наближенне до життя.

Це дозволяє показати всі типи кардинальностей та дотриматися 3NF в межах однієї моделі.

## Примітка щодо проєкту
Модель створена з фокусом на строгу нормалізацію. Усі прямі M:N зв'язки розгорнуті через асоціативні таблиці з власними атрибутами (наприклад, фіксація ціни в момент покупки у OrderItem). Використано строгу типізацію ключів (UUID) та зафіксовано обмеження унікальності (UK) для полів і композитних ключів.

## Опис
Клієнти реєструються в системі, можуть зберігати кілька адрес доставки та додавати страви в обране. При оформленні замовлення фіксується адреса, призначається кур'єр, а позиції замовлення зберігають кількість та актуальну ціну страви. Також діє реферальна система, де користувачі можуть запрошувати друзів.

## Сутності
- **User** — клієнт платформи
- **Address** — збережені адреси доставки клієнта
- **Courier** — кур'єр, що доставляє замовлення
- **MenuItem** — страва з меню
- **Promotion** — акційна пропозиція для страв
- **Order** — замовлення клієнта
- **OrderItem** — позиція у замовленні (асоціативна сутність Order <-> MenuItem)
- **Favorite** — список улюблених страв (асоціативна сутність User <-> MenuItem)
- **Friendship** — реферальна система (асоціативна сутність User <-> User)

## Зв'язки
- **User -> Address:** 1:N (один клієнт має багато адрес)
- **User <-> User:** M:N через Friendship (self-referencing, користувач запрошує інших користувачів)
- **Promotion -> MenuItem:** 1:N (одна акція діє на багато страв)
- **User <-> MenuItem:** M:N через Favorite (користувач додає страви в обране)
- **User -> Order:** 1:N (клієнт робить багато замовлень)
- **Address -> Order:** 1:N (на одну адресу оформлюється багато замовлень)
- **Courier -> Order:** 1:N (кур'єр доставляє багато замовлень)
- **Order <-> MenuItem:** M:N через OrderItem (замовлення містить багато страв із фіксацією ціни та кількості)
